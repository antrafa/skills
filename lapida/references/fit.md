# FIT — demand, competition, monetization and next tests

Goal: say what is known about fit, what is not, and the cheapest test that would
move the riskiest assumption from `none` to `strong`. This phase does not
measure market fit — no conversation can. It lists the signals that would
confirm it and the evidence that exists today.

## Sources

Competitors, prices, market sizes and demand signals are looked up with web
search, and each enters with its link and the date you read it. What you cannot
look up is labeled `hypothesis — to verify` with the search or interview that
would close it. Never fill this phase from memory as if it were research.

## Required fields

| Field | Filled when |
|---|---|
| Alternatives and competitors | direct competitors, indirect ones, the current workaround and doing nothing — each with a source or a hypothesis label; restate the workaround and doing nothing here even if earlier phases covered them, so the block stands alone |
| Fit signals | the 2–4 observable signals that would confirm fit, each with current evidence `strong` / `weak` / `none` |
| Monetization | who pays, how much, and why that price (`business` only) |
| Next tests | at least one test of the riskiest assumption: hypothesis, test, numeric success criterion, deadline |
| Recommendation | `go` / `pivot` / `stop`, conditional on the first test |

## Methods

**Riskiest Assumption Test** (Rik Higham, 2016; builds on Eric Ries's
Build-Measure-Learn from *The Lean Startup*). Before building an MVP, run the
smallest experiment that tests the one assumption CHALLENGE ranked riskiest.
Write it as a test card (Strategyzer / David Bland):

> We believe `<hypothesis>`. To verify, we will `<test>`. We measure
> `<metric>`. We are right if `<numeric criterion>` by `<date>`.

Write every card with its five slots spelled out, never compressed into an
arrow line: a test with no named metric cannot be read a month later.

Cheap test formats, cheapest first: problem interviews following The Mom Test
(5–10 people), a landing page or waitlist, a fake-door button, a concierge or
Wizard-of-Oz run (a human behind what looks automated), a paid pilot or
pre-sale.

**Fit signals**, by class:

- `business`: repeat use without prompting, willingness to pay (pre-sale,
  deposit), referrals, the Sean Ellis test (≥ 40% "very disappointed" without it).
- `internal product`: adoption without mandate, the old workaround abandoned,
  time or incidents reduced by a measured amount.
- `personal project`: the user still uses it after a month.

## Recommendation

- `go` — riskiest assumption testable soon and cheaply; the test is the next step.
- `pivot` — the problem held but the audience, solution or model did not; name
  what changes.
- `stop` — the problem did not hold, or doing nothing costs less than building.
  Saying so early is the skill doing its job.

## Question repertoire

- "Who already solves this, even badly? What do they charge?"
- "What would make you give up on this idea in three months?"
- "What number, a month after the test, tells us it worked?"
- "Who pays — the user, their boss, or nobody?"
