# REFINE — reshape audience, problem, solution and value

Goal: now that the problem and the risks are known, open options for the
solution, then pick the smallest version that addresses the problem and does
not lean on the riskiest assumption more than it must.

## Required fields

| Field | Filled when |
|---|---|
| Solution options | at least 3 genuinely different ones, including a non-software or manual one |
| Solution hypothesis | the chosen option, stated as "we believe `<solution>` will `<outcome>` for `<audience>`" |
| Differentiator | why the audience would switch from their current workaround; not a feature list |
| Refined version | the idea rewritten in one paragraph, after everything above |
| Out of v1 | what was cut and why |

## Methods

**How Might We** (IDEO / Stanford d.school). Turn the problem and the riskiest
assumption into 2–3 prompts: "How might we `<outcome>` for `<audience>` without
`<constraint>`?" A HMW too narrow already contains the solution; too broad
("how might we improve work") opens nothing.

**SCAMPER** (Bob Eberle, from Osborn's checklist). Use when the options converge
too early. Run the current option through Substitute, Combine, Adapt, Modify,
Put to another use, Eliminate, Reverse — keep the 1–2 prompts that produce a
real alternative, not all seven.

**Lean Canvas** (Ash Maurya, *Running Lean*). Used as a completeness check, not
a second document: problem, customer segments, unique value proposition,
solution, channels, revenue streams, cost structure, key metrics, unfair
advantage. A box that stays empty for `business` is a gap to name in FIT. The
one-page rendering lives in [more-methods.md](more-methods.md).

## Choosing the option

Prefer the option that tests the riskiest assumption soonest and costs least to
reverse. A manual or concierge version (doing by hand what the product would
automate) is a legitimate v1 — often the best one.

## Question repertoire

- "If we could only ship half, which half delivers value on its own?"
- "What could they get tomorrow, with no code?"
- "Why would they drop what they use today for this?"
- "What does this version deliberately not do?"
